# 安全与客户数据

仅由获授权管理员在客户批准的 AWS 账号、区域和专用业务 Realm 使用。本项目不是托管身份服务，不承诺生产 SLA。

- 不提交真实 JSON、映射名单、Secret、密码、令牌、二维码、HAR、数据库/运行备份。`.gitignore` 不能替代逐文件审核。`mapped-private` 和运行目录只保存在客户受控存储，POSIX 目录 700 / 文件 600。
- Secret 通过隐藏交互或指定 SSM SecureString / Secrets Manager 引用读取，不写命令行参数。不要关闭 MFA；可使用批准的短期管理令牌。管理事件不得记录含 Secret 的请求正文。
- 身份必须精确绑定 Realm、企业、应用及已验证 UserId。邮箱来自管理员批准映射，不意味着企微验证了邮箱。不得增加自动按邮箱关联、员工自行填写身份、通配信任或删掉拒绝流程。
- 受控 Cookie 只复用与当前批准映射完全一致的临时身份；不得用普通 `auth-cookie` 替换。映射停用不是已签发 token / STS / Quick 会话的即时撤销机制。
- Users 为零不等于无个人信息：身份映射、在线/离线会话及日志仍需保留策略。业务员工清理不涉及 master 管理员。
- 新客户从零初始化无需清理。仅旧环境清理必须有明确用户名确认、UUID 回读与私有备份。清理后不能一键恢复旧持久用户登录；备份不包含可恢复密码/会话，也不保证普通 API 能恢复原 UUID。
- 不在扫码时自动注册 Quick 席位。首次注册须确认收费；迁移不替换原 Quick 用户及资产归属。离职撤权与席位费用须由各系统单独处理。
- 固定组件版本并审核供应链。Keycloak 26.6.4 的 transient-users 为实验功能，扩展使用内部 SPI；升级后必须重新跑隔离协议测试和客户现场验收。

安全问题优先通过仓库 Security 私密报告（若已启用），否则先联系维护者取得私密渠道。公开 Issue 只提供脱敏现象、版本和复现条件，不上传客户数据。
