# 企业微信扫码登录 Quick：已有环境增量接入

> 本页仅用于已有环境补齐经过验证的企微绑定，属于迁移前的准备步骤。若绑定和登录已就绪，直接使用 [管理员映射临时用户实施](管理员映射临时用户实施.md)，不要重复配置。迁移后不要再用本页脚本覆盖活动登录流程。

适用范围：**已有带社区 wecom 插件的 Keycloak 26.6.4，以及已配置好的 Quick Web / Desktop、IAM 联合身份和获批 Quick 用户。** 本脚本仅补入口与绑定，不安装服务器、不创建用户/席位、不修改 AWS 权限。只有 Keycloak 安装好的新客户应使用 [首次部署图文说明](扫码登录快速实施.md)，不要填写本页的已有 UUID/ARN 模板。

客户交付包不包含当前测试企业的账号、Secret、绑定数据或 AWS 凭据。

## 下载后：CloudShell 从上传开始

在目标 AWS 账户打开 CloudShell，右上角 **Actions → Upload file** 上传 `quick-wecom-transient-sso-v1.0.0.zip`。然后逐行执行：

```bash
quick_wecom_dir="$(mktemp -d ./quick-wecom.XXXXXX)"
unzip -n quick-wecom-transient-sso-v1.0.0.zip -d "$quick_wecom_dir"
cd "$quick_wecom_dir/quick-wecom-transient-sso"
python3 --version
python3 -c "import boto3; print(boto3.__version__)"
cp wecom-sso.example.json customer-wecom.json
nano customer-wecom.json
```

每次解压到新目录，避免误执行之前上传的旧脚本。若 ZIP 被浏览器改名，先用 `ls -l *.zip` 核对，第二行改为实际文件名；不要仅上传 ZIP 就运行其他目录下的旧脚本。Python 版本需 3.10+；本次使用 boto3 1.43.110。缺少 boto3 时经客户允许执行 `python3 -m pip install --user boto3==1.43.110`。CloudShell 的账号和区域必须与客户参数一致。

在 nano 中填好下一节要求的真实参数，按 Ctrl+O、Enter 保存，Ctrl+X 退出。**参数模板里的示例值不能直接用于客户环境。** 下文所有命令都在这次解压的 `quick-wecom-transient-sso` 目录中执行。

## 1 · 先核对企业微信（人工）

![企业微信应用字段](screenshots/01-wecom-application.png)

进入 **企业微信管理后台 → 应用管理 → 自建应用详情**，记录 AgentID，确认获批员工在可见范围内。CorpID 在 **我的企业 → 企业信息 → 企业 ID**。Secret 只通过隐藏输入保存，不写进 JSON、截图或聊天。

**查看 Secret：** 在该应用详情点击 **Secret → 查看**。若弹窗显示“Secret 将通过『企业微信团队』下发”，由管理员点击 **发送**，再到自己的企业微信客户端打开 **企业微信团队** 消息查看，按页面要求完成身份验证。将值粘贴到第 3 步 `store_secret.py` 的隐藏输入提示；它不是 AgentID，也不是通讯录同步 Secret。已有安全保存的值时无需再次发送。

![企业微信开发者设置](screenshots/02-wecom-features.png)

向下找到开发者接口，分别核对：

| 设置 | 填什么 | 注意 |
|---|---|---|
| 企业微信授权登录 → Web 网页 → 授权回调域 | Keycloak 域名，例如 `sso.example.com` | 仅域名，不带 `https://` 和路径 |
| 网页授权及 JS-SDK → 可信域名 | 同一 Keycloak 域名，按后台要求验证 | 不能替代上一项 |
| 企业可信 IP | Keycloak 任务所在子网的 NAT 公网出口 IP | 多出口全部填写；不是 ALB 或本机 IP |
| 通讯录 → 员工详情 → 账号 | 真实 UserId | 不是显示姓名，也不按邮箱猜测 |

图片为既有脱敏实拍；2026-10-13 重新核对了上述菜单、字段和区别。客户必须核对自己的值。域名验证文件须在 `https://客户Keycloak域名/WW_verify_实际文件名.txt` 可直接访问（不需登录、不跳转）；已验证的应用无需为了重跑脚本重新创建应用或修改域名。

## 2 · 填一份客户参数

将 [wecom-sso.example.json](../wecom-sso.example.json) 另存为 `customer-wecom.json`，替换全部示例值。

| 参数 | 从哪里获取 |
|---|---|
| `origin` / `realm` / `saml_alias` | Keycloak 的域名、Realm 名及 SAML 客户端的 IDP-Initiated SSO URL name；平台管理时也可从平台配置页读取 |
| `aws_account` / `region` | 目标客户账户和 Quick 身份区域；脚本会用 STS 校验账号 |
| `corp_id` / `agent_id` | 第 1 步的企业 ID / 应用 AgentID |
| `secret_parameter` | 为该客户单独命名的 SSM SecureString 路径 |
| `portal_managed` | 平台创建的 Realm 填 `true`，独立管理的 Realm 填 `false` |
| `users[].kc_id` / `username` / `email` | 已有 Keycloak 用户 UUID、用户名、受控邮箱；不创建新用户 |
| `wecom_user_id` | 员工本人真实企业微信账号，保留原大小写 |
| `quick_username` / `role_arn` / `provider_arn` | 已执行的 AWS 配置包结果、平台导入结果和 AWS 实际记录 |

脚本内部绑定键是 `lower(wecom_user_id)`，不加 CorpID 前缀。Keycloak UUID、用户名和邮箱，以及 Quick principal/RoleSessionName 均保持原值。例：扫码身份 `MemberOne` 可以绑定到既有 `employee-one`；**不需要把 Quick 用户改名为企业微信账号**。

平台管理的 Realm 必须先部署支持 `portal.wecom.approval.v1` 的适配版本；运维验证服务版本后，才为该 Realm 写入能力标记 `portal.wecom.adapter=v1`。不能只手工添加标记绕过旧版平台“不允许外部 IdP”的检查。脚本会维护精确批准清单；客户版不包含本项目服务器发布脚本。

## 3 · 保存密钥、预检查（不配置登录）

在已经登录客户 AWS 账号的终端运行。需要 Python 3.10+ 和 boto3；CloudShell 通常已提供，缺少时先按客户软件管理流程安装。

```bash
python3 wecom_sso.py plan --config customer-wecom.json
python3 store_secret.py --account 123456789012 --region ap-northeast-1 --parameter /customer-quick/wecom-secret
python3 wecom_sso.py check --config customer-wecom.json
```

第二条中的账号、区域、参数路径必须与 JSON 一致；按提示粘贴 Secret，输入不回显。它会新建一个加密参数，**已有参数则拒绝覆盖**；轮换走客户批准的密钥流程。它不会更新 Keycloak Provider，也不代表密钥已经验证有效。

`check` 会提示输入 Keycloak 管理账号/密码。如果客户要求 MFA，不得关闭 MFA 来运行脚本：改用批准流程获取的短期 `QUICK_SSO_ADMIN_TOKEN`（通过受控终端环境注入），或 `--admin-secret-id` 指定同一客户 AWS 账户中已批准的 Secrets Manager 管理凭据引用。脚本不会导出登录 Token。

检查范围：账号、社区插件、Realm 基线、两个客户端、用户 UUID、邮箱、现有绑定、SAML 映射、Quick principal、IAM provider issuer/证书及对应员工的信任语句。不会验证企业微信 Secret 的真实可用性，也不会证明 Desktop extension 已存在。

如果报必改密码/MFA enrollment，先让员工通过正常流程完成；脚本不自动删除 required actions。绑定冲突、异常认证流程、额外 broker、受控邮箱不符等一律停止，不自动覆盖。脚本目前仅接受平台基线的逐用户 IAM 信任格式；其他已审查架构需先适配测试，不强行修改客户 IAM。

## 4 · 应用并启用

```bash
python3 wecom_sso.py apply --config customer-wecom.json --journal apply-01.json
python3 wecom_sso.py enable --config customer-wecom.json --journal enable-01.json --wecom-console-confirmed
python3 wecom_sso.py verify --config customer-wecom.json
```

- `apply`：新建拒绝未绑定用户的首次登录流程、**默认禁用**的社区 Provider、明确批准的已有用户绑定及管理批准记录；保留密码、客户端、AWS 资源和 Quick 账号。不会启动登录切换。
- `enable`：确认企业微信人工设置已核对后，仅启用 `wecom` Provider，在原登录页增加扫码按钮；不修改 master 管理员、不强制全员跳转、不更改 Quick 的账户级 SSO 设置。
- `verify`：使用全新无登录 Cookie 的请求，检查 Web SAML 和 Desktop OIDC 都能跳到官方企业微信授权地址，验证 CorpID、AgentID 和完整回调。**通过不等于实际扫码登录成功**。

`--journal` 必须是新的文件名，不会覆盖；包含绑定标识等个人数据但不含 Secret，请按客户隐私要求保管。脚本中途失败可能保留禁用的部分配置，查看 journal 与现场后再处理；缺少/不完整的认证流程会拒绝继续，不盲目补写。重复执行已完整的相同配置不会重复创建用户或绑定，但每次写操作仍需新的 journal 文件。

## 5 · Quick 设置与本人扫码验收（人工）

![Quick SSO 菜单](screenshots/06-quick-admin-navigation.png)

Quick **管理账户 → 身份 → SSO**：填写 `plan` 输出的 `quick_sso_url`。已有正确入口就保留；不是 Metadata 下载地址。如果此前仍指向其他 Realm，需按客户变更流程切换，并保留独立管理员入口。

![Quick 扩展访问](screenshots/07-quick-extension-access-entry.png)

Quick **管理账户 → 权限 → 扩展访问**：保留指向本 Realm 的 Desktop access；再确认主工作区 **扩展** 中有关联且活跃的 Desktop extension。两个对象都要有，不能只创建 access。完整字段见 [完整手动配置图文说明](完整手动配置图文说明.md) 的第 9 步。

先让获批员工打开 `quick_sso_url` 本人扫码并核对身份；通过后在批准窗口将 Quick「服务提供商启动的 SSO」状态设为「开启」并保存，保留独立管理员入口。再从正常入口验证 Web 退出重登，并在另一台电脑验证 Desktop 本人扫码、回环回调及刷新。Keycloak 或 Desktop 离线会话可跳过扫码，不能将缓存直入算作扫码验收。不替用户扫码，不截取 Token/授权码。未绑定成员、停用用户等负向验收需要专门获批的测试身份；只有一位获批成员时，不把“双用户隔离测试”标记为通过。

平台绑定用户继续支持停用、启用和撤销 Keycloak 会话；企业微信会话由企业微信管理。平台不会给绑定用户重置临时密码，以免扫码后触发强制改密。原本地密码未被脚本删除，是保留的备用登录方式；需要纯扫码策略时，应另行评审并测试管理恢复路径。

## 回退与新增客户

```bash
python3 wecom_sso.py disable --config customer-wecom.json --journal disable-01.json
```

此回退仅禁用目标 Realm 的扫码 Provider，原密码登录、AWS/Quick 用户、IAM 角色和配置不变，已建立的会话不会自动撤销。遇到其他配置漂移也可执行该禁用动作，但仍需合法 AWS/Keycloak 管理权限。它不删除绑定、审计或密钥；需要撤销已登录会话时，由管理员另外执行。操作目标 RTO 为一分钟内完成 API 禁用（不含获取管理权限的时间），不是实测恢复承诺。

新增客户使用 [首次部署图文说明](扫码登录快速实施.md)，无需管理平台；本页仅用于已有完整登录环境补充扫码。**本包不是从零部署 VPC、ECS、RDS 或 Quick 订阅的一键安装器。** 基础设施与可选 MCP 自动化不在本脚本范围。

开发验证：`python3 -m unittest tests.test_wecom_sso -v`。目前在 macOS 上执行，Linux/Windows 客户环境尚需验证；未声称已经在其他客户生产环境验收。
