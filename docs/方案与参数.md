# 方案说明与需要维护的参数

## 最终运行状态

企业微信认证真实员工，Keycloak 创建本次会话的临时身份并输出 SAML / OIDC，Quick 使用原来的用户与授权。新客户从初始化起，Keycloak Users 列表为空；用户再次扫码也不新增持久行。

不是“没有用户体系”：Quick 仍有用户，管理员仍维护受控映射。也不是影子用户方案：不会在首次扫码时落一条永久员工记录。不依赖应用 API 能读取企微邮箱。

## 系统分别维护什么

| 系统 | 内容 | 如何配置 |
|---|---|---|
| 企业微信 | 自建应用、可见范围、真实 UserId、回调域、可信 IP、Secret | 企业管理员手动，见首次部署图文 |
| Keycloak | 两个协议客户端、临时 IdP、批准映射、拒绝流程、受控会话复用 | 先部署自建扩展，再运行专用脚本 |
| AWS IAM | SAML Provider、每员工联合角色、用户名及邮箱精确信任 | 初始配置脚本生成 CloudFormation；迁移/清理只读核对 |
| Quick | 用户、角色、Web SSO、扩展访问、Desktop 扩展 | 用户经费用确认由脚本注册；三个控制台表单手工填写 |

## 客户输入和自动生成的值

| 参数 | 来源 / 维护要求 |
|---|---|
| AWS account、region | 客户自己的账号和 Quick 实际身份区域 |
| origin、realm | 客户 HTTPS Keycloak 地址及独立业务 Realm；不是 master |
| CorpID、AgentID、WeCom UserId | 企业微信管理后台；不能用显示姓名或邮箱替代 UserId。配置中 UserId 取小写，2–64 位字母/数字/点/下划线/连字符 |
| Secret | 交互式保存为客户 SSM SecureString；JSON 只填参数路径 |
| username、email、quick_role | 管理员批准的 Quick 身份；不能随意改名或按同邮箱认领 |
| SAML alias | Realm 内 SAML 客户端的登录 URL 别名；完整 URL 由脚本输出 |
| Role ARN、SAML Provider ARN | 首次部署自动创建读取；已有环境迁移必须沿用核对后的原值 |
| OIDC sub | 新客户初始化前自动生成并固定保存在 state.json；不是持久员工 UUID。仅旧环境迁移才沿用已验证的原 UUID |
| realm_id、策略指纹 | 脚本自动核对，禁止跨客户复制策略或手工拼接指纹 |

初始参数用 [new-customer.example.json](../config/new-customer.example.json)。迁移仍使用客户原部署清单，私有快照由脚本从真实系统读取；本仓库不提供一份带真实员工值的 policy 让客户照抄。

## 操作顺序

```text
准备 Keycloak + 社区插件 + 附带扩展 / Quick 订阅 / 企微应用
→ 直接初始化临时模式 Realm、映射、协议客户端和受控会话流程（Users=0）
→ 创建 IAM Provider、每员工角色
→ 经费用确认注册 Quick 用户
→ 手工填写 Quick SSO、扩展访问、扩展
→ 启用 wecom-mapped
→ Web / Desktop 扫码验收
→ verify --require-active：Quick 已激活，Keycloak Users=0
```

仅旧持久账号的已有兼容环境从迁移开始，不重复创建 IAM 或收费用户。已清理环境必须使用 `retirement/after-snapshot.json` 校验，不能使用旧快照要求已删除账号继续存在。

## 日常维护与限制

当前脚本是固定名单的初始化/迁移/清理工具，不是自助用户管理平台。新增、离职、改名、换企微应用、Secret/签名证书轮换都需变更评审和各系统核对；不要只编辑映射 JSON，或重跑首次部署去接管已有资源。

同一有效浏览器会话可在 OIDC 与 SAML 间复用扫码；不同浏览器、Cookie 过期、强制认证及退出后的会话状态会影响扫码次数。禁用映射不立即撤销既有凭据，需按客户流程撤销 Keycloak、Quick 和 AWS 会话/授权。
