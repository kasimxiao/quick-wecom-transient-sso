# 项目维护与验收

本仓库只交付管理员映射临时用户方案。初始配置脚本用于建立准确身份合同，不是最终运行模式。按[实施入口](../README.md)完成初始化、迁移、受控会话、实测和显式清理。

## 构建环境

需要 Python 3.10+、Node.js 20+、Java 21 / Maven，以及运行隔离集成测试的 Docker。先在项目根目录执行：

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
npm ci --ignore-scripts
python3 -m unittest discover -s tests -q
npm run docs:build
npm run docs:check
mvn -f mapped-provider/pom.xml clean package
```

自建扩展版本为 **1.1.0**，项目交付版本为 **1.0.0**，两者不是同一个版本号。构建输出为 `mapped-provider/target/quick-wecom-mapped-transient-1.1.0.jar`。JAR 不包含社区企微插件。

若没有已验证的社区镜像，可从固定上游源码构建，再叠加本项目扩展：

```bash
docker build -t quick-wecom-community:a777528-26.6.4 community-provider
docker build \
  --build-arg COMMUNITY_IMAGE=quick-wecom-community:a777528-26.6.4 \
  -t quick-wecom-mapped:1.1.0 mapped-provider
docker pull python:3.12-slim
python3 scripts/test_new_customer_local_keycloak.py
python3 scripts/test_mapped_transient_keycloak.py
```

上游源码版本和下载校验值固定在 `community-provider/upstream.lock.json` 与 Dockerfile。生产部署请将批准镜像推到客户自己的镜像仓库并固定 digest，保留原数据库、HTTPS hostname、反向代理和密钥参数。不要把测试用 `start-dev` 或内存/文件数据库配置直接用于生产。

## 自动测试能证明什么

| 验证 | 范围 | 不代表什么 |
|---|---|---|
| Python / Java 单元测试 | 映射约束、精确目标、配置漂移拒绝、迁移/回滚、清理边界、打包 | 不代表真实企微扫码或 AWS 授权通过 |
| 真实隔离 Keycloak 集成 | 无上游邮箱、SAML/OIDC/PKCE、稳定 sub、会话复用、强制重登、清理后 Users=0 | 企微 API 为模拟服务，不访问真实 STS 或 Quick |
| 文档与 ZIP 检查 | 本地链接、截图打包、HTML 新鲜度、命令语法、示例离线计划、敏感模式 | 不能代替客户逐屏验收 |
| 参考环境实测 | 用户已确认 Quick Desktop 扫码成功；之后清理的 Users=0 已独立回读 | 清理后再次真实 Desktop 扫码尚无明确记录；不是客户环境验收 |

2026-10-16 独立项目验证：73 项 Python 测试、10 项 Java 测试、真实隔离 Keycloak 的临时用户 / 受控会话 / 清理后新登录测试已通过。文档检查覆盖 10 份文档及本地引用、命令语法与离线计划。

每个客户仍须用无旧 Cookie 的真实 Web / Desktop 分别测试批准员工及未批准员工，核对原 Quick 用户、角色、邮箱、稳定 subject 和 Users 数量。只有进入原身份才算通过，不是停在角色选择页就完成。

## 打包离线交付

完成以上构建、测试后：

```bash
mkdir -p dist
python3 scripts/package_sso.py \
  --with-provider \
  --output dist/quick-wecom-transient-sso-v1.0.0.zip
shasum -a 256 dist/quick-wecom-transient-sso-v1.0.0.zip
```

打包器只收录逐项列出的源码、示例、20 张已审核截图、生成 HTML 和指定 JAR；不扫描客户目录。已有 ZIP 不会被覆盖，重复打包应指定新文件名。`--source-only` 不包含 HTML / JAR，不能冒充完整离线交付包。

打开包内 `quick-wecom-transient-sso/README.html` 开始实施。私有 `customer.json`、Secret、映射快照、HAR、审计日志、运行状态和 `.ops/` 均不发布。发布前仍应人工审核所有新增内容和图片，自动敏感模式扫描不是完整 DLP。

## 清理后的日常维护

清理员工必须先得到客户逐人删除批准；只删除当前快照确认的 Keycloak UUID，不能删除 Quick 用户或 IAM 角色。清理后使用 `mapped-private/retirement/after-snapshot.json` 作为新核对基线。不要再使用“原账号仍存在”的旧快照执行验证。

旧 JSON 备份不能恢复密码/会话，也不能保证恢复原 UUID。清理后只允许回滚会话复用层，不能一键退回旧持久用户模式；完整恢复依赖客户自行验证过的数据库/Realm 恢复流程。

新增员工、离职撤权、映射变更仍是审批操作，当前没有自动同步接口。映射变更会影响策略指纹与会话校验；不要手改 policy 后忽略相关核对。已有 STS、Quick 和离线会话需分别处理。实验功能或内部 SPI 升级前重跑全部验证，再安排现场测试。
