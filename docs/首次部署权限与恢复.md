# 权限与中断恢复

本页适用于 [初始部署](扫码登录快速实施.md) 和 [管理员映射临时用户实施](管理员映射临时用户实施.md)，不替代客户安全审批。

新客户直接创建临时模式 Realm、批准映射、IAM 资源及经确认的 Quick 用户，**不创建/绑定/删除 Keycloak 员工**；迁移、会话复用只核对 AWS / Quick，不修改其资源。清理阶段只允许删除逐一确认的旧 Keycloak UUID，需要对应用户读取/删除权限。清理后不得自动回滚旧持久用户模式。

## 开工权限

- 已安装 Keycloak 26.6.4 + 社区 wecom 插件 + 附带映射/受控 Cookie 扩展，开启 transient-users，受控终端可访问，HTTPS 证书有效；有批准的创建业务 Realm/client/profile/flow/broker 以及读取 Users 数量的 权限。需要读取 serverinfo 和 master 日志策略，但脚本不修改 master。
- master 管理员请求体明细记录必须关闭，避免创建 broker 时记录 Secret。检测到启用时脚本停止，由客户管理员按审计策略处理；不要关闭审计事件本身。
- 使用客户 AWS 临时登录凭据，不创建长期 Access Key。脚本通过 STS 核对账号，使用客户配置中的 Quick/SSM/CloudFormation 区域。
- Quick 由客户开通支持 IAM 联合登录的 Enterprise 订阅，`default` namespace 就绪。企业微信应用、真实 UserId、可见范围、域名验证和服务器出口均已确认。

## AWS API 权限清单

这是调用范围，不是可直接照搬的 `Resource:*` 管理员策略。由客户 IAM 管理员根据 plan 输出的名称、API 支持的 resource/tag condition 和组织 SCP 制定执行角色。

| 阶段 | API 权限 |
|---|---|
| 身份检查 | `sts:GetCallerIdentity` |
| Secret | 指定参数的 `ssm:PutParameter`（仅新建）、`ssm:GetParameter`，指定 KMS key 的必要加解密权限 |
| 可选管理凭据 | 指定 secret 的 `secretsmanager:GetSecretValue` 和 KMS 解密；仅使用 `--admin-secret-id` 时需要 |
| Quick 检查 | `quicksight:DescribeAccountSubscription`、`DescribeNamespace`、`ListUsers`、`DescribeUser`、`ListTagsForResource` |
| CloudFormation | `ValidateTemplate`、`CreateStack`、`DescribeStacks`、`DescribeStackResource`、`GetTemplate`；不调用 UpdateStack/DeleteStack |
| IAM 创建和读回 | 新生成名称的 `CreateSAMLProvider`、`TagSAMLProvider`、`GetSAMLProvider`；`CreateRole`、`TagRole`、`GetRole`、`PutRolePolicy`、`ListRolePolicies`、`ListAttachedRolePolicies`、`GetRolePolicy` |
| 付费用户 | 经审批目标的 `quicksight:RegisterUser` 及所需标签权限；该阶段才创建席位 |

IAM 由 CloudFormation 使用操作者批准的权限创建。堆栈启用命名 IAM 确认、终止保护及 Retain；失败不会由脚本删除或替换角色。组织若要求专用 CloudFormation 服务角色、权限边界或私网代理，须先评审适配，不能直接扩大权限或关闭校验。

资源归属通过部署标签、固定的 StackId 和 CloudFormation 的逻辑资源 → 实际资源映射核对；不要求 IAM 返回 `aws:cloudformation:*` 系统标签。角色名称、RoleId、信任条件和策略仍必须逐项匹配。

## 状态、冲突和恢复

`customer-run` 默认 0700，文件默认 0600（POSIX），包含员工信息但不含明文 Secret/密码/Token。备份到批准的受控存储；Windows 另按 ACL 限制访问。

1. 保留同一配置、同一目录。配置摘要、部署 ID 和资源绑定；改 JSON 或换目录会拒绝接管已有资源。
2. `CREATE_IN_PROGRESS` 不是失败。等待堆栈完成后重复原 aws 命令，不会新建第二个堆栈。
3. 创建响应丢失后，仅读到原部署标记和精确身份才能继续。若未读到、请求明确失败或认证流程不完整，会停止，不把“暂未读到”当作“未创建”。
   Quick 注册明确成功后，用户或标签读取暂时返回资源不存在时，仅进行有界只读等待，不再次调用 RegisterUser。超出等待仍停止并保留 pending；人工核对实际身份和部署标签后，可用原目录、原参数重跑 `users` 补齐已成功的记录。静态 `verify` 仍直接报告读取错误，不隐藏漂移。
4. 不要删 state.json、改 pending、删除重建角色或换目录重试。管理员结合 Keycloak 管理事件、CloudFormation 事件及 CloudTrail 核实原请求，按变更流程恢复；本版不会盲目重试结果不明的注册。
5. CLI 创建 `operation.lock` 防止本目录并发，正常退出自动移除。异常结束留锁时，先由管理员确认原进程和其他实施人均不在运行，再按批准流程解除锁，不要直接启动第二份部署。
6. 稳定 subject、RoleId、证书、客户端、映射、权限或收费角色漂移会停止，不覆盖。本版仅做固定清单首次配置；追加员工、Secret/证书轮换和许可升级另行评审。

管理员短期令牌由脚本在到期前续期；交互登录仅保留内存中的 refresh token，Secret 模式重新读取同一批准凭据，静态 `QUICK_SSO_ADMIN_TOKEN` 不自动替换。明确 401 最多重试一次；若续期被拒绝或发生超时，保留原目录核查，不修改令牌寿命、不重放结果不明的创建请求。SAML 加密及 Artifact 绑定必须关闭；旧配置未显式保存这两个 false 默认值也能通过核验，误开启则停止。

`disable` 关闭 wecom-mapped 并阻断受控 Cookie 的新认证，不卸载，不撤销会话、不删除收费席位、不退订。员工没有脚本默认密码；管理员保留独立登录。撤销会话、停用身份和取消费用需另行审批。

schema=2 / fresh-mapped-transient 状态不得与旧版 schema=1 混用。首次流程配置中断会保留 pending 并停止重试，请管理员审查部分配置；不得清空状态强行续跑。完整成功后同配置可重复核验。`verify` 默认不写本地状态或远端配置，`--route-check` 会启动登录会话，`--require-active` 用于真实登录后的 Quick 激活验收。

## 已批准的测试环境重建

这不是报错后的恢复办法。确需从零重测时，先备份配置、批准映射和资源清单，核对测试用户的组及内容权限，保留独立管理员入口。首次脚本遇到现有 Realm、同名 IAM 资源或同邮箱 Quick 用户会正确停止，不能伪造 owner/state 来接管手工资源。清理只针对已确认可丢弃的测试资源，不删除订阅、服务器、Secret 或其他用户。

即使名称和 ARN 不变，重建也会更换 Realm ID、签名证书、IAM RoleId 和 OIDC subject。旧 Quick 身份不能仅凭同邮箱直接复用，旧 Web/Desktop 会话必须重新认证；配置快照不包含私钥或会话，不保证恢复原身份。完成批准的清理并确认目标确实为空后，才用新的运行目录按首次部署流程执行；不要复用旧 state 或 metadata。

企微应用、Quick SSO 和 Desktop access/extension 可以保留：逐项对照新生成的 `parameters.json` 核对域名、Issuer、端点、Client ID 和 RelayState，再完成真实登录。地址未变化不等于证书和身份未变化。SSO 地址有变化时编辑保存；Desktop access 当前编辑页只支持名称/描述，OIDC 参数变化需经批准重建，删除 access 会连带删除关联 extension，不能直接照搬 SSO 的编辑方式。

**重建后 Desktop 没出现二维码或报 `User info request failed (HTTP 500)`：** 没有二维码可能是有效会话复用，500 本身不能证明是缓存、IAM 权限或 Keycloak 故障。先退出 Desktop 并重新发起登录；需要强制扫码验收时，由管理员核对并经批准仅撤销该测试员工的在线会话，必要时处理对应离线会话，再从 Desktop 重新发起。二维码在客户端打开的系统浏览器中，不在 Quick 管理页面中。全新认证仍失败时，记录时间并核对客户端与 Keycloak 日志、实际 Quick 身份及扩展配置，不反复删除重建资源、不延长令牌时长。浏览器显示成功后，还需确认 Desktop 主界面、正确员工身份及 Keycloak Users=0；一次恢复不等于长期续期验证通过。

## 输出与安全

- Metadata 从真实 Realm 读取并自动配置 AWS；approved-mapping.json 保存批准映射和 ARN；稳定 subject 在首次远程写入前生成，保存在 state.json，不对应持久员工行。
- 每员工一个角色，精确限定 issuer、audience、username 和 Email tag，不采用独立数组的交叉授权，也不授 AWS 管理权限。
- 新模式未获批或映射不一致成员拒绝。均不按邮箱自动关联、不邀请成员认领、不在扫码时注册 Quick。
- 同邮箱 Quick 用户已存在时改走已有关联方案，不替换其资产归属。
- 本地测试不代表客户 SLA 或实际扫码通过。生产前仍需客户安排备份恢复、域名证书、Keycloak 补丁、Secret 轮换、出口变更、费用和访问审计。
